# 第3段階：苦手復習の精度向上

起点は最新main `aec24c7`（第2段階のPR #2取り込み済み）です。検証には合成履歴のみを使用します。生徒の履歴の削除・初期化・再採点、問題データの編集は行いません。

## 調査結果：不具合と設計上の課題

実装上の不具合:

- `start('weak')` と `start('scheduled')` が `qs` のみを検索するため、ボス問題の誤答・期限が自動復習に出ない。ホームの期限件数にもボス問題が含まれない。
- `test('weak')` がボス問題や通常問題で最小問題数を補い、苦手に無関係な問題を混ぜる。対象ゼロでも通常テストを始める。
- `pickTargetedList` の直近出題への減点によって、期限付きの問題より未学習問題が優先される。
- 1問だけのセットや最後の問題で誤答すると、同じ問題を直後に再出題する。
- 理由の自己評価が未確定の状態で `start` や `test` がセッションを置き換えると、メモリ上の仮加点が次の保存で確定してしまう。

学習設計上の課題:

- 従来の苦手順は主に累積誤答数×3で決まり、期限や回復状況による順位の変化が小さい。
- 通常学習の40%期限・30%苦手・30%新規という配分では、復習対象だけで1セットを満たせる場合も新規問題が入る。
- 未克服の誤答記録と習熟度2が併存する履歴では、1回の理由確認付き正解で習熟度3「完全習得」へ上がる一方、間違いノートは未克服のままになる。

後者はアルゴリズムの設計判断であり、コードの例外やデータ破損と同一視しません。今回の変更は説明可能なルールによる改善案であり、学習効果が実験で保証された方法ではありません。

## 出題順

対象は全744問。既存の `mistakes`、`reviews`、`confidence`、`q.lastSeen`、習熟度のみを使用します。新しい履歴フィールドや保存形式は追加しません。

1. 「復習期限到来」「未克服の誤答」「shaky / unrated / slow」のいずれかを満たす問題を復習対象にする。
2. 復習対象を未学習等の対象外問題より先に選ぶ。
3. 復習対象同士では直近5分以内に回答した問題を後ろへ回す。対象から削除せず、他の復習候補がなければ選ぶ。
4. 同じ直近出題区分の中では下記スコアの高い順。最後は問題IDで安定した順序にする。

| 要素 | 点数 |
|---|---|
| 期限到来 | +20 |
| 期限超過 | 超過時間（時間単位）、最大+10 |
| 未確認・自信なし・時間をかけた正解 | +6 |
| 誤答履歴 | `min(誤答回数,6) × 2 / (1 + min(別日の正答連続数,3))` |
| 習熟不足 | `3 − 習熟度` |

誤答総数には上限と回復実績による減衰を設けます。正解率だけで判定しません。履歴には全回答の時系列がないため、直近の正答状況は既存の「別日の確認済み正答連続数」と自己評価を代理情報として使い、存在しない直近N問の正答率を推測しません。

通常学習は復習対象から先にセットを満たし、足りない分だけ通常問題から補充します。単元・技能等で指定されたリストでは、その範囲を広げず同じ順位規則を使います。忘却対策は期限到来の問題から選びます。期限対象がない場合の通常学習への切り替えは維持します。

苦手テストは復習対象だけで最大10問。対象が1問なら1問で実施し、対象がなければ通知して開始しません。テスト正解で習熟度を上げない既存の条件は維持します。

復習画面には「復習の理由」として期限・誤答数・別日の正答実績・理由の確認状況を表示します。スコアを成績や学力の測定値として表示しません。

## 習熟度と反復

- 未克服問題は、別日の確認済み正答が既に2回ある場合に限り、次の理由確認付き正解で「完全習得」へ昇格できます。克服の3日条件と整合させます。
- 既に保存されている習熟度3を、この条件変更だけで下げません。不正解時の既存の減点は維持します。
- ヒント使用・同セット内の再挑戦・テストは習熟度昇格に加算しません。同日に繰り返しても別日実績は増やしません。
- 理由があやしい・未確認の場合は仮の習熟度と苦手克服を取り消します。加点上限に達している場合も、未確認の学習日を確定しないようにします。別モード・テストへ移る場合も自己評価を未確認として確定処理します。
- 同セットの誤答再挑戦は1問題につき最大1回を維持し、他の問題を挟める場合に残します。直後に同じ問題になる場合や1問セットでは繰り返さず、既存の5分後の復習予定へ回します。未確認の理由に対する10分後の予約も維持します。

## 互換性・制限

保存キー `rikaTangoV2`、schemaVersion 92、問題ID、744問の問題データ、入力判定ルールを維持します。旧履歴の値を書き換えて新アルゴリズムに合わせる移行処理はありません。

日付は従来どおりブラウザーの暦日、期限と直近出題は端末時計を使います。日付をまたぐ短い間隔が丸24時間の間隔になる保証はありません。スコアの係数、5分の出題分散、復習優先の配分には生徒を対象とした効果検証が必要です。復習対象が多い間は新規問題が減り、対象が1問だけなら分散できません。旧履歴にない時系列情報は復元しません。ブラウザーストレージの同時更新等の制限は第1段階の説明のとおりです。
